# CLAUDE.md — Kulova Shopify App

## Context
Solo founder project: **Kulova**, AI customer-service chat widget for the Shopify App Store.
English-first product. Flat pricing: Free (~100 conversations/mo), Pro $29/mo, Company $149/mo.
Differentiator: flat pricing, no per-resolution fees (documented pain point of Tidio/Gorgias).
Exit goal 1–3 years. Owner is anonymous, self-serve/inbound only, minimal budget.

## Working rules (IMPORTANT)
- User communicates in Finnish. Keep replies short — long messages go unread.
- ALWAYS double-check before destructive changes. Take a git checkpoint commit before risky edits.
- NEVER touch kulova.com production (repos `kulovav1`, `kulova_backend` main) without explicit user confirmation — live customers use it. Backend changes must stay backward-compatible: legacy clients send `businessId`, Shopify path sends `shopDomain`.
- Never commit secrets. `.env` is gitignored. KULOVA_INTERNAL_KEY value is stored in Vercel (sensitive) and user's password manager only.
- Ask before: production deploys, schema changes, deleting anything.

## Architecture
- **This repo (`~/kulova-app`)**: Shopify embedded app. React Router template + Prisma session storage + theme app extension at `extensions/kulova-widget` (block `kulova_chat.liquid`, uid in `shopify.extension.toml`).
- **Backend (`~/kulova-backend`)** → https://kulova-backend.vercel.app — Vercel auto-deploys from `main`. Endpoints: `/api/chat`, `/api/botinfo` (both accept `shopDomain` OR legacy `businessId`), `/api/shopify-sync` (internal; requires header `x-kulova-key` = env `KULOVA_INTERNAL_KEY`; creates/returns `businesses` row for a shop).
- **Supabase** project `eacfiiscsdqdcoduyzkk`: tables `businesses` (has `shopify_domain` text + unique partial index; `owner_email` now nullable), `conversations`, `messages`, `login_codes` (RLS OFF — known security issue, fix after Shopify launch).
- **Widget** (`extensions/kulova-widget/assets/kulova-widget.js`) calls backend `/api/chat` with `{message, sessionId, shopDomain}`. Reads shop from `data-shop="{{ shop.permanent_domain }}"`.
- **Vercel project for this app**: `mramalones-projects/kulova-app` → https://kulova-app.vercel.app
- `shopify.app.toml`: application_url + redirect_urls → kulova-app.vercel.app; scopes `read_products,read_orders,read_customers`; GDPR webhook subscriptions added; routes exist: `webhooks.customers.data_request.tsx`, `webhooks.customers.redact.tsx`, `webhooks.shop.redact.tsx` (TODOs inside point to Supabase data deletion — implement before submission review if time allows; responding 200 is the minimum bar).

Bugs found & fixed along the way:
  - `shopify.app.toml` GDPR webhooks (`customers/data_request`, `customers/redact`, `shop/redact`) must use `compliance_topics = [...]` field, not `topics = [...]` — Shopify rejects the old form now ("The following topic is invalid").
  - `prisma migrate deploy` (in `shopify.web.toml`'s `dev` command and `package.json`'s `setup` script) failed with P3005 against the Postgres DB because the only migration on disk was a stale **sqlite** migration from the original template and we'd created the schema via `db push`, not migrations. Deleted `prisma/migrations/`, switched both commands to `prisma db push` (consistent with the isolated-schema strategy above). This would have broken prod too (`Dockerfile` CMD runs the same `setup` script) — fixed there as a side effect.
  - `extensions/kulova-widget/shopify.extension.toml` had a malformed `uid` (40 hex chars, not the valid 32) — regenerated a real UUID via `node -e "console.log(require('crypto').randomUUID())"`.
  - The widget-activation deep link in `app._index.tsx` used the deprecated `{uuid}` (extension uid) form for `activateAppId`. Current Shopify docs require `{api_key}/{handle}` (app's `client_id`, not the extension uid) — fixed to `` `${process.env.SHOPIFY_API_KEY}/kulova_chat` ``.
  - `app/routes/app.plans.tsx` referenced `PRO_PLAN`/`COMPANY_PLAN` (imported from the server-only `shopify.server.ts`) inside the client-rendered `PLANS` array, which broke React Router's server/client code-splitting ("Server-only module referenced by client"). Fixed by duplicating the plan-id strings as literals in the client-facing array instead of importing them.
  - Shopify's Billing API refused all requests with "Apps without a public distribution cannot use the Billing API" until the user manually set **Public distribution** for the app in the Dev Dashboard (dev.shopify.com/dashboard → kulova-app → App distribution) — this is a one-time, irreversible choice tied to the app record itself, not something settable via code/CLI/toml.
  - Windows-specific dev-loop quirk: stopping the `shopify app dev` background process often leaves orphaned `node.exe` children holding port `9293` (theme preview) and a lock on `node_modules/.prisma/client/query_engine-windows.dll.node`, causing `EADDRINUSE`/`EPERM` on the next start. Fix each time: `tasklist /FI "IMAGENAME eq node.exe"` → `taskkill /PID <pid> /F` for stragglers before restarting.

NOTE: `app/routes/app.tsx` has a pre-existing (template) TS error — `s-app-nav` not in the Polaris JSX types — unrelated to the above work, not yet fixed.

- GDPR webhooks fully implemented (not just 200-OK stubs). Key finding while implementing: the chat widget/backend (`kulova-backend/api/chat.js`) never captures Shopify customer identity — `conversations`/`messages` are keyed only by an anonymous per-visit `session_id` + `business_id`, no customer id/email/phone anywhere. So `customers/data_request` and `customers/redact` correctly have nothing to export/delete (documented in-code, not a TODO). `shop/redact` (fires on uninstall) does real work: deletes the Prisma `Session` rows (unchanged) plus, via raw SQL through the same Postgres connection (`db.$queryRaw`/`$executeRaw` — these backend tables aren't in this app's Prisma schema, only `Session` is), the shop's `businesses`/`conversations`/`messages` rows in the shared `public` schema, scoped strictly by `shopify_domain`. Verified against a throwaway test business+conversation+message row (created and deleted via the exact same queries) — cascaded correctly, real data (5 businesses/2 conversations/28 messages at the time) confirmed untouched.
